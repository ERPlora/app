## ADR-0053 · Firma del APK Android: keystore compartida (alias `erplora`) entre el Hub Tauri (`com.erplora.hub`) y el Bridge Android standalone — 2026-06-22

- **Estado:** **aceptada** (mantener la clave **compartida** por ahora; pre-lanzamiento). El estado
  ya en vigor es clave compartida; esto documenta la decisión de conservarla y la opción futura de
  separarla. La política de firma/claves = columna del humano; esta redacción + el wiring de CI/firma
  = columna IA. **Separar las claves queda como decisión abierta del humano** (ver Consecuencias).
- **Contexto:** ERPlora distribuye **dos apps Android distintas**, cada una con su `applicationId`:
  (1) el **Hub Tauri** (`com.erplora.hub`, eje B = `tauri`), que **incluye el bridge como sidecar**
  en el mismo APK ([`tauri.md`](../hub/apps/tauri.md), ARQUITECTURA.md §2.7); (2) el **Bridge Android
  standalone** (app **Kotlin** separada), que solo se instala en el combo `cloud + web-PWA` cuando el
  Hub corre en navegador y necesita hardware local ([`bridge.md`](../hub/apps/bridge.md)). La primera
  release firmada del Hub Tauri se publicó el 2026-06-22 (`tauri-release.yml` → `build-android` →
  `apksigner` con alias `erplora` → `s3://erplora-downloads/app/latest/erplora-app.apk`), reusando la
  **misma keystore** que ya firmaba el `bridge-android`. Surge la pregunta: ¿misma clave o claves
  distintas entre las dos apps?
- **Hechos de Android que enmarcan la decisión:**
  1. La clave de firma solo debe ser **consistente dentro de cada app** (todas las updates de un
     `applicationId` con su misma clave). Entre apps distintas es indiferente.
  2. **Compartir clave entre dos apps NO es obligatorio.** Solo haría falta para interoperar por
     mecanismos a nivel de firma (`sharedUserId` —deprecado—, permisos `signature`, providers
     restringidos por firma). ERPlora **no usa nada de eso**: Hub ↔ Bridge se comunican por
     **WebSocket en `127.0.0.1:12321`** (red), no por IPC de Android. ⇒ **no hay necesidad técnica**
     de compartir la clave.
  3. Como ERPlora distribuye el **APK directo** (S3, no Play App Signing), la keystore **es** la clave
     real de firma: su filtración permitiría firmar una "actualización" maliciosa de la(s) app(s).
  4. Una app publicada **no puede cambiar de clave** (rompe las updates; en Play el "upgrade" es
     limitado, en APK directo es imposible).
- **Decisión:** **una sola keystore (`erplora-app.keystore`, alias `erplora`) para ambas apps**, por
  **simplicidad operativa** (un único secreto que guardar/proteger, un solo set de secrets en CI). Es
  legítimo porque no hay requisito técnico de clave común. El alias `erplora` está hardcodeado en
  `tauri-release.yml` (`apksigner --ks-key-alias erplora`) y los secrets `ANDROID_KEYSTORE_BASE64` /
  `ANDROID_KEYSTORE_PASSWORD` viven a nivel de organización en GitHub.
- **Consecuencias:** + gestión de claves mínima (un fichero, un backup, un set de secrets); + identidad de proveedor coherente (mismo vendor). − **mayor radio de impacto** si la keystore se filtra: comprometería **ambas** apps en vez de una (mitigable endureciendo el secreto). − **irreversible por app una vez distribuida:** el **Bridge** ya está **bloqueado** a `erplora`; el **Hub Tauri** se publicó el 2026-06-22 con `erplora` ⇒ su primera release fue el **último momento limpio** para darle clave propia sin romper updates. **Opción futura (humano):** si se prioriza el **aislamiento de seguridad** entre los dos productos, separar las claves — viable de forma limpia **solo** mientras la app correspondiente tenga ~0 instalaciones; forma recomendada = **una sola keystore con dos alias** (`erplora-hub` / `erplora-bridge`) → dos claves distintas en un solo backup, con un cambio pequeño en el workflow (alias hoy fijo a `erplora`).
- **Docs afectados:** este log; [`architecture/hub/apps/tauri.md`](../hub/apps/tauri.md) (sección
  «Release Android — empaquetado, firma y publicación del APK»);
  [`architecture/hub/apps/bridge.md`](../hub/apps/bridge.md) (nota de firma del Bridge Android).
  Sin cambio de código por esta decisión (estado actual ya = clave compartida); separarlas en el
  futuro tocaría `hub/.github/workflows/tauri-release.yml` (alias por app) = trabajo del humano.
